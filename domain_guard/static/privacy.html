Privacy notice

Last updated: November 27, 2026

1. Scope and responsibility

DomainGuard is a personal software project developed by Tarun Puri in Alberta, Canada. This notice describes the hosted website and the loopback-only version of the software. Production supports browser-based public DNS and email record checks. When the hosted website service is enabled, it can perform a single bounded HTTPS HEAD observation through an isolated Vercel Sandbox. More comprehensive website scanning remains local-only.

2. Hosted website and public DNS checks

The example report uses fixed data. If you submit a domain for online DNS checking, your browser sends DNS requests to Google Public DNS over HTTPS, which receives the queried names and your network address. Requests omit credentials and referrers and request no EDNS client subnet disclosure. Google processes requests under its Public DNS privacy policy. When hosted website checks are enabled, the submitted hostname is also sent to a Vercel server function. The function resolves and screens public DNS addresses, reserves capacity using an Upstash Redis counter, and starts a time-limited Vercel Sandbox for a single HTTPS HEAD request to the public destination. The destination server may observe the Sandbox network address, submitted hostname, connection time and DomainGuard user agent. The scanner does not submit credentials or follow redirects. If admission is denied or checks are unavailable, the DNS-only report remains available. The quota counter stores aggregate timestamps and counts rather than a per-visitor domain history. DomainGuard itself does not create accounts, set cookies or use analytics or advertising scripts. Vercel Preview Authentication controls access to protected previews and may use authentication cookies. The font is served locally when installed. The site is hosted by Vercel, which may process network addresses, browser information, request timestamps and access logs under its privacy policy.

3. Local scanning

When explicitly enabled on your computer, the local server receives the submitted hostname. It temporarily holds scan results, random access credentials, scan times and rate-limit records in memory. The server does not intentionally log submitted domains, scan IDs or bearer credentials. It retains no permanent application scan history.

To perform checks, the local scanner sends DNS queries to its configured resolver and bounded HTTPS and TLS connections to the screened public destination. These services may observe the queried name, your network address, connection times and the scanner user agent. They may retain information under their own policies. DomainGuard does not control them.

4. Retention, access and deletion

Local jobs expire 15 minutes after submission and are removed by periodic cleanup. The in-memory rate-limit history is retained for its bounded rate window. Stopping the local server clears its application memory. Results displayed in the browser and files you copy, print or download remain under your control until you close or clear them. Do not share private results or credentials.

5. Safeguards and limits

Local scans use randomly generated access credentials, loopback restrictions, bounded requests and verified TLS for outbound HTTPS. These reduce risk but do not guarantee confidentiality or eliminate all vulnerabilities. The loopback development server must not be exposed through a public proxy or tunnel. Other processes on your device and your browser may have access to local information.

6. Questions and privacy rights

For a privacy question or a request about information the project operator controls, contact the maintainer through the GitHub profile. Do not post personal information or sensitive security details in public issues. For sensitive inquiries, do not post private findings in public issues; contact the maintainer via the GitHub profile first. Applicable privacy rights are not waived by this notice.
