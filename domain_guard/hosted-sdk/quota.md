# Zero-spend quota gate

The controller requires a dedicated, single-region free Redis database with no payment method or paid marketplace plan. Upstash REST supports atomic Lua EVAL. Keep eviction disabled. Do not expose the endpoint or credentials to browsers. Use environment variables on the trusted gateway only. The application must fail closed on missing, expired, corrupted or unavailable quota state. A failed or ambiguous reservation is never retried.

Initialize the dedicated database key once through the provider console, before enabling the pilot: SET domainguard:scan-quota:v1 v1:0:0:0:0:0 NX. Never reset it as part of deployment, restart or error recovery. The script uses a single atomic check-and-update, provider time and UTC windows to cap admissions at 10/day and 100/month with 35 seconds between reservations. A quota reservation is spent even if a subsequent scan fails. The database stores aggregate counters and timestamps only, not hostnames or client IPs.

These conservative limits are pilot defaults, not billing guarantees. Stay on Vercel Hobby; no Pro or paid service upgrades. A provider outage or exhausted quota disables hosted website checks rather than falling back to an unmetered scanner. DNS-only remains the existing separate browser mode. Before enabling the gateway verify the actual free plan, provider atomic behavior including concurrent requests and missing-state handling, service credentials and live SDK execution. The Node tests mock the REST response; they do not prove actual database atomicity. No public API is enabled by this change.
